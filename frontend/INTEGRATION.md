# 우리텃밭 프로젝트 연결

기존 로그인·카카오 연동·메뉴·마이페이지·환경설정을 유지하고, 최신 텃밭 화면을 홈에 연결했습니다.

## 실행

1. backend 폴더에서 가상환경을 만들고 활성화한 뒤 `pip install -r requirements.txt`를 실행합니다.
2. 기존 backend/.env의 DATABASE_URL, JWT_SECRET, 카카오 설정을 확인합니다.
3. backend 폴더에서 `uvicorn main:app --reload --port 8000`을 실행합니다.
4. frontend 폴더에서 `npm ci`를 실행합니다.
5. frontend/.env의 `VITE_API_URL=http://localhost:8000`을 확인합니다. 기존 카카오 클라이언트 ID는 유지합니다.
6. `npm run dev`를 실행하고 http://localhost:5173 에 접속합니다.
7. 비회원 시작 또는 카카오 로그인 → 기존 첫 실행 안내 → 내 농장 → 농장 추가.

농장이 없는 상태로 시작합니다. 새 농장을 만들고 지역(예: 경기 양평군)을 입력하면 현재 날씨를 자동 조회합니다.

## 연결된 화면과 기능

- `/home`: 농장 목록·추가·수정·삭제, 6칸 텃밭, 작물 심기·물주기·성장 단계·수확·기록·오늘 할 일.
- 햄버거 버튼 → 업로드한 기존 `/menu`. 메뉴·프로필·환경설정은 기존 React 컴포넌트를 그대로 사용합니다.
- `/journals`: 사용자별 재배일지. 물주기·성장·수확·메모 기록 포함.
- `/mypage`: 농장 수·재배 중 작물·수확·일지 통계를 저장 데이터에 연결.
- `/diagnosis`, `/pointshop`: 원본에 구현 파일/API가 없어서 준비 중 화면을 연결했습니다.
- 날씨: 최신 해·구름·비·눈·안개·밤 효과, 상단 하늘만 적용. 수동 날씨 선택은 없습니다.
- 텃밭·작물·폰트 원본, 작은 나무 팻말, 최신 간격과 안내 문구 제거를 유지했습니다.

## 저장 방식

FastAPI에 사용자별 `garden_states` 테이블과 `GET/PUT /garden/state`를 추가했습니다. 서버 시작 시 새 테이블만 생성합니다. 업로드에 농장 테이블 정의가 없으므로 농장·작물·일지·효과 설정을 검증된 JSON 문서로 함께 저장합니다. 향후 정규화한 농장/재배 테이블을 추가할 때 이 저장 계층을 바꾸면 됩니다.

GET으로 가져온 revision을 PUT에 보내며 다른 탭의 변경을 덮어쓰지 않게 검사합니다. 저장 실패 시 화면에 오류와 재시도 버튼이 표시됩니다. 저장되지 않은 변경이 있으면 창을 닫을 때 브라우저 안내가 나옵니다.

카카오 계정 연동의 기존 데이터 선택/이전 흐름에도 garden_states를 포함했습니다. 새 사용자에게 기존 데모 농장을 자동 삽입하지 않습니다. 이전 독립 데모 사이트의 localStorage 데이터를 자동으로 계정에 가져오지는 않습니다.

## 구현 경계

- 기존 로그인/메뉴 스타일과 충돌하지 않도록 텃밭 화면은 같은 출처의 iframe에 격리했습니다. React가 로그인 API 호출·저장·메뉴 이동을 담당하며, 프레임에 인증 토큰을 전달하지 않습니다.
- 기존 서버의 포인트·경험치를 사용합니다. 데모용 물주기 +5P/수확 +20P 증가는 제거했습니다. 실제 포인트 적립/교환 API는 원본에 없어 추가하지 않았습니다.
- 성장 단계는 기존 예시처럼 직접 변경합니다. AI 진단은 실제 서비스 연동이 필요합니다.
- 브라우저의 위치 권한과 외부 Open-Meteo 접속이 필요합니다. API는 현재 모델 날씨이며 관측값과 차이가 날 수 있습니다.
- 서버와 프론트엔드를 다른 주소로 배포할 때 기존 CORS allow_origins와 카카오 redirect_uri 설정을 해당 도메인으로 함께 조정해야 합니다.
- 기존 공유 데모 URL과 이 프로젝트는 별도 실행 대상입니다. 이 파일의 서버를 실행하면 실제 로그인·서버 저장을 사용하는 통합 화면이 열립니다.

## 검사

- 프론트엔드 `npm run build`: 통과. dist/에 빌드 결과 포함.
- `python backend/tests/test_garden.py`: 임시 SQLite에서 실제 로그인·저장·재조회·사용자 분리·검증·충돌·통계·카카오 계정 데이터 이전 검사.
- 기존 실서비스 DB나 실제 카카오 계정에 접근하지 않았습니다. 실제 브라우저 화면과 카카오 OAuth 로그인은 별도 확인이 필요합니다.
- 압축에서 node_modules와 Windows venv는 제외했습니다. 설치 명령으로 실행 환경을 다시 구성하세요.
